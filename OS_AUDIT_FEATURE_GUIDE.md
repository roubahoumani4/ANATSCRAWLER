# OS Audit Feature Implementation

## Overview
The OS Audit feature has been successfully integrated into ANATSCRAWLER. This feature allows users to:
- Register their machines for security audits
- Download and install a Lynis-based audit agent
- View detailed security audit reports with scores, warnings, and suggestions
- Track machine status and audit history

## Database Models

### 1. OSAuditMachine Model (`server/models/OSAuditMachine.ts`)
Stores information about registered machines for OS auditing.

**Fields:**
- `machineId` (String, unique): Unique identifier for the machine
- `owner` (ObjectId): Reference to the User who owns this machine
- `ownerName` (String): Name of the person who owns/uses the machine
- `machineName` (String): Display name for the machine
- `machineHostname` (String): System hostname
- `ipAddress` (String): IP address of the machine
- `operatingSystem` (String): OS type and version
- `lynisVersion` (String): Installed Lynis version
- `agentStatus` (Enum): 'active', 'inactive', or 'pending'
- `lastAuditDate` (Date): Date of the last audit performed
- `registrationDate` (Date): When the machine was registered
- `agentInstallationToken` (String, unique): Token for agent installation
- `agentInstalledDate` (Date): When the agent was installed
- `isActive` (Boolean): Whether the machine is actively monitored

### 2. OSAuditReport Model (`server/models/OSAuditReport.ts`)
Stores audit reports generated by the Lynis agent.

**Fields:**
- `reportId` (String, unique): Unique report identifier
- `machine` (ObjectId): Reference to OSAuditMachine
- `owner` (ObjectId): Reference to the User
- `auditDate` (Date): When the audit was performed
- `machineName` (String): Name of the audited machine
- `ipAddress` (String): IP of the audited machine
- `ownerName` (String): Name of the machine owner
- `operatingSystem` (String): OS information from audit
- `auditScore` (Number): Overall security score (0-100)
- `warnings` (Number): Count of warnings found
- `suggestions` (Number): Count of suggestions
- `systemHardening` (Number): System hardening score
- `findings` (Array): Detailed findings with test ID, description, result, severity
- `sections` (Mixed): Detailed audit sections
- `rawReport` (String): Raw Lynis report output
- `status` (Enum): 'completed', 'failed', or 'pending'
- `auditDuration` (Number): Duration of audit in seconds
- `lynisVersion` (String): Version of Lynis used

## API Routes (`server/routes/os-audit.routes.ts`)

### Machine Management Endpoints

**POST /api/v1/os-audit/machines/register**
- Register a new machine for OS audit
- Required: `machineName`, `ipAddress`, `ownerName`
- Optional: `operatingSystem`, `machineHostname`
- Returns: Registered machine with `agentInstallationToken`

**GET /api/v1/os-audit/machines**
- Get all machines for the authenticated user
- Returns: Array of all registered machines

**GET /api/v1/os-audit/machines/:machineId**
- Get details of a specific machine
- Returns: Machine details

**PUT /api/v1/os-audit/machines/:machineId**
- Update machine details (name, owner, OS, hostname)
- Returns: Updated machine

**DELETE /api/v1/os-audit/machines/:machineId**
- Delete a machine and all associated reports
- Returns: Success message

### Report Management Endpoints

**POST /api/v1/os-audit/reports**
- Submit an audit report from the agent
- Authentication: Token-based (using `agentInstallationToken`)
- Required: `agentInstallationToken`, `auditData`
- Returns: Created report

**GET /api/v1/os-audit/reports**
- Get all audit reports for the user
- Supports pagination: `limit` and `offset` query params
- Returns: Array of reports with pagination info

**GET /api/v1/os-audit/reports/:machineId**
- Get all reports for a specific machine
- Returns: Array of machine reports with machine info

**GET /api/v1/os-audit/reports/latest/:machineId**
- Get the latest audit report for a machine
- Returns: Most recent report

**GET /api/v1/os-audit/reports/details/:reportId**
- Get detailed information about a specific report
- Returns: Full report with populated machine details

### Agent Management Endpoints

**POST /api/v1/os-audit/agent/heartbeat**
- Agent heartbeat confirmation
- Authentication: Token-based
- Returns: Machine status

**GET /api/v1/os-audit/stats**
- Get overall OS Audit statistics for the user
- Returns: 
  - `totalMachines`: Total registered machines
  - `activeMachines`: Machines with active agents
  - `inactiveMachines`: Machines without active agents
  - `totalReports`: Total audit reports
  - `averageAuditScore`: Average security score
  - `totalWarnings`: Warnings from latest 10 reports
  - `totalSuggestions`: Suggestions from latest 10 reports

## Agent Installation Script

The installation script (`os-audit-agent-[machineId].sh`) is automatically generated and downloaded from the UI.

**What the script does:**
1. Detects the operating system (Ubuntu/Debian, RHEL/CentOS/Fedora, or Arch)
2. Installs required dependencies (curl, wget, git, build tools)
3. Installs Lynis security auditor
4. Creates the agent directory `/opt/anat-os-audit`
5. Generates the agent script that:
   - Runs Lynis security audit
   - Extracts key metrics (score, warnings, suggestions)
   - Parses system information (OS, hostname, IP)
   - Creates JSON report
   - Sends report to the server via HTTP POST
   - Sends heartbeat to confirm agent is active
6. Sets up daily cron job for automatic audits (runs at 2 AM)

**Usage:**
```bash
sudo bash os-audit-agent-[machineId].sh
```

## Data Storage

All data is stored in MongoDB:
- **Collection**: `os_audit_machines` (OSAuditMachine documents)
- **Collection**: `os_audit_reports` (OSAuditReport documents)
- Database: Uses the existing `anat_security` database configured in environment

## Security Features

1. **Token-based Agent Authentication**: Each machine gets a unique installation token
2. **User Isolation**: Users only see their own machines and reports
3. **Owner Verification**: Only the owner can view machine reports
4. **IP Tracking**: Machine IP address stored and validated
5. **Owner Identification**: User must enter their name before audit begins
6. **Audit Trail**: Complete audit history per machine

## Usage Workflow

1. **User Registration**:
   - User navigates to `/os-audit`
   - Clicks "Register Machine"
   - Enters: Name, Machine Name, IP Address, OS (optional)

2. **Agent Installation**:
   - Click "Download Agent" for the machine
   - Copy the installation token
   - Run script: `sudo bash os-audit-agent-[machineId].sh`

3. **Automated Audits**:
   - Agent runs daily at 2 AM
   - Or manually: `sudo /opt/anat-os-audit/agent.sh`

4. **View Reports**:
   - Reports appear automatically in the "Audit Reports" tab
   - Click to view detailed findings
   - See scores, warnings, suggestions per machine

## Troubleshooting

### Agent Installation Issues
1. Ensure root access: `sudo`
2. Check internet connection for package downloads
3. Verify Lynis installation: `which lynis`

### Report Not Appearing
1. Check agent logs: `tail -f /opt/anat-os-audit/agent.log`
2. Verify token matches in registration
3. Check server connectivity from machine

### Database Issues
1. Verify MongoDB connection in logs
2. Check database user permissions
3. Ensure collections are created
